# Thesis Project – Integration of Machine Learning Components in Web-Based Software Systems

This repository contains the complete reference implementation for the Bachelor's thesis
_"Integration of Machine Learning Components in Web-Based Software Systems: A Comparative Analysis of Architectural Patterns"_.
The project investigates how the choice of ML integration strategy affects performance,
fault tolerance, and maintainability of a web application, using a purpose-built
e-commerce product-review application as the substrate.

Six architectural variants are compared along two axes:

- **Integration variant** – where inference runs: Embedded (E), Self-hosted (S), eXternal (X)
- **Communication mode** – how the result is returned: Synchronous (Sync), Asynchronous (Async)

The resulting variants are **E-Sync, E-Async, S-Sync, S-Async, X-Sync, and X-Async**.

## Infrastructure: environment file

All infrastructure credentials are loaded from a `.env` file at `thesis-sentiment-shop/.env`.
This file is gitignored. Create it before starting any container:

```
DB_NAME=sentimentshop
DB_USER=sentimentshop
DB_PASSWORD=<choose>
DB_ROOT_PASSWORD=<choose>
DB_URL=<your url>
RABBITMQ_DEFAULT_USER=sentimentshop
RABBITMQ_DEFAULT_PASS=<choose>
HUGGINGFACE_API_TOKEN=<your token>    # required for X-Sync and X-Async only
```

## Quick start

### 1 – Start the required infrastructure

Each variant needs a different subset of containers. Start only what the variant requires:

| Variant | Command                                                            |
| ------- | ------------------------------------------------------------------ |
| E-Sync  | `docker compose up -d mariadb`                                     |
| E-Async | `docker compose up -d mariadb`                                     |
| S-Sync  | `docker compose up -d mariadb inference-service`                   |
| S-Async | `docker compose up -d mariadb rabbitmq inference-service-consumer` |
| X-Sync  | `docker compose up -d mariadb`                                     |
| X-Async | `docker compose up -d mariadb rabbitmq`                            |

Host port mapping:

| Service                  | Host port |
| ------------------------ | --------- |
| MariaDB                  | 13306     |
| RabbitMQ (AMQP)          | 15673     |
| RabbitMQ (management UI) | 15672     |
| Python inference service | 18000     |

### 2 – Build and run the backend

For the embedded variants, generate the ONNX model artefact first (one-time step):

```bash
cd thesis-sentiment-shop/scripts/export-model
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python export-model.py
```

Then build and run the chosen variant:

```bash
cd thesis-sentiment-shop
mvn -P<profile> clean install
mvn -P<profile> -pl web spring-boot:run
```

Available profiles: `e-sync`, `e-async`, `s-sync`, `s-async`, `x-sync`, `x-async`.
The default profile (`stub`) starts the application without any real classifier.

### 3 – Start the frontend

```bash
cd thesis-sentiment-shop-frontend
npm install
ng serve
```

The frontend is available at `http://localhost:4200`. It proxies API calls to `http://localhost:8080`.
